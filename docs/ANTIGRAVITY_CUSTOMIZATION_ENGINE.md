# Архитектура движка кастомизаций Antigravity (Customization Engine)

> **Назначение документа:**  
> Данный документ является фундаментальным инженерным руководством и базой знаний по поведению ядра Antigravity (Antigravity IDE, Antigravity 2.0 CLI/Desktop и `language_server_windows_x64.exe` на базе Go/Cortex).  
> Документ подробно описывает механизм обнаружения (discovery), приоритеты загрузки, семантику исключений (exclude), а также детальные результаты эмпирических тестов для навыков (Skills) и плагинов (Plugins) во всех сценариях глобальной и проектной конфигурации.

---

## 1. Компоненты системы и источники истины

Движок Antigravity оперирует двумя взаимосвязанными подсистемами:
1. **Antigravity IDE (VS Code Fork):**  
   Интегрированная среда разработки. Управляет контекстом ассистента во время активной сессии редактора.  
   - Источником истины активности плагинов является файл манифеста `plugin.json` (поле `"disabled": true/false`).
   - Источником конфигурации путей и списков исключений являются конфигурационные файлы `skills.json` и `plugins.json`.
2. **Antigravity CLI / Desktop 2.0 (`language_server_windows_x64.exe`):**  
   Сервер языка и агентский бэкенд на Go (`package customizations`, модуль `cortex/customizations`).  
   - Читает глобальный конфигурационный файл `~/.gemini/config/config.json` (секция `"plugins": { "<name>": { "enabled": true/false } }`).
   - Загружает навыки и плагины согласно 5-уровневой иерархии источников (`CustomizationSourceConfig`).

## 2. Иерархия и приоритеты загрузки (Loading Priority)

При формировании контекста ИИ языковой сервер и IDE опрашивают источники в строго определенном порядке приоритета:

| Уровень | Тип источника | Расположение | Особенности и поведение |
| :--- | :--- | :--- | :--- |
| **Приоритет 1** | **Встроенные (Built-in)** | `~/.gemini/antigravity/builtin/skills`<br>`~/.gemini/antigravity-ide/builtin` | Системные компоненты ядра Google. **Строго Read-Only**. Не могут быть отключены или заблокированы пользовательскими конфигами. |
| **Приоритет 2** | **Проектные декларации (Workspace Declared)** | `<WorkspaceRoot>/.agents/skills.json`<br>`<WorkspaceRoot>/.agents/plugins.json` | Пользовательские папки или отдельные элементы, явно подключенные к текущему проекту через секцию `entries`. |
| **Приоритет 3** | **Дефолтное глобальное обнаружение (Default Global Discovery)** | `~/.gemini/config/skills/`<br>`~/.gemini/config/plugins/` | Физические каталоги по умолчанию. Сканируются ядром напрямую с диска **без явных записей в entries**. |
| **Приоритет 4** | **Локальные каталоги проекта (Workspace Local Folders)** | `<WorkspaceRoot>/.agents/skills/`<br>`<WorkspaceRoot>/.agents/plugins/` | Автономные ресурсы, созданные локально внутри репозитория разработчика. |
| **Приоритет 5** | **Глобальные декларации (Global Declared Libraries)** | `~/.gemini/config/skills.json`<br>`~/.gemini/config/plugins.json` | Внешние библиотеки, подключенные через секцию `entries` (например, `E:\AI\skills-global`, `E:\AI\plugins`). |

## 3. Механика отключения: Дефолтная папка vs Подключенная библиотека

Главное архитектурное открытие, подтвержденное эмпирическими тестами: **механизм отключения элементов принципиально различается в зависимости от того, где физически расположен ресурс**.

### 3.1. Ресурсы в дефолтной глобальной папке (`~/.gemini/config/...`)
- Поскольку папки `~/.gemini/config/skills` и `~/.gemini/config/plugins` опрашиваются через **Default Global Discovery (Приоритет 3)**, они не имеют отдельной записи в секции `entries`.
- Чтобы отключить такой навык или плагин глобально, система вынуждена использовать корневое поле `exclude: ["item_name"]` в `skills.json` / `plugins.json`, либо выставлять `"disabled": true` в `plugin.json` и `"enabled": false` в `config.json`.
- **Эффект универсального черного списка (Machine-Wide Killswitch):**  
  Корневое поле `exclude` в глобальном конфиге и поле `"disabled": true` в `plugin.json` трактуются ядром Antigravity как **глобальный безусловный запрет**.  
  Даже если проект на уровне Приоритета 2 (`.agents/skills.json` или `.agents/plugins.json`) попытается явно подключить этот ресурс через `entries: [{ "path": "..." }]`, **ядро Antigravity проигнорирует проектную декларацию и заблокирует ресурс**!

### 3.2. Ресурсы в подключенной библиотеке (`E:\AI\...`)
- Подключенные библиотеки загружаются через **Declared Configurations (Приоритет 5)**.
- Каждая библиотека представлена объектом в секции `entries`:
  ```json
  {
    "path": "E:/AI/skills-global",
    "exclude": ["my_skill"]
  }
  ```
- Когда навык или плагин отключается глобально, его имя добавляется **строго в локальный массив `exclude` конкретной записи `entry`**, а корневой `exclude` остается чистым!
- При этом для плагинов манифест `plugin.json` **НЕ помечается как `"disabled": true"`**, и в `config.json` не пишется `"enabled": false"`.
- **Результат:** Глобально элемент выключен (библиотека его не отдает), но **локальный проект может свободно импортировать его через `.agents/skills.json` / `.agents/plugins.json`**!

## 5. Двухуровневый алгоритм переключения плагинов (Dual-Tier Toggle Architecture)

Для обеспечения безупречной работы кейса **C4** модуль `services/actions.js` реализует специализированную архитектуру:

```
                  ┌──────────────────────────────┐
                  │ togglePluginGlobal(pluginId) │
                  └──────────────┬───────────────┘
                                 │
                 Является ли плагин стандартным
                 (~/.gemini/config/plugins)?
                                 │
                 ├───────────────┴───────────────┐
                ДА                              НЕТ (Подключенная библиотека)
                 │                               │
        ┌────────┴────────┐             ┌────────┴────────┐
        │ Стандартный путь│             │ Библиотечный путь│
        └────────┬────────┘             └────────┬────────┘
                 │                               │
  1. Пишет disabled в plugin.json  1. Гарантирует disabled: false в plugin.json
  2. Пишет enabled в config.json   2. Удаляет запись из config.json (снимает killswitch)
  3. Пишет в корневой exclude      3. Пишет строго в entry.exclude в plugins.json
```

### Кодовая реализация в `services/actions.js`:
```javascript
if (isDefaultGlobal) {
  // Standard Global: Write to plugin.json and config.json
  setPluginManifestDisabled(targetDir, !enable);
  setAntigravityPluginEnabled(dirName, enable);
  // Sync with global plugins.json root exclude
  for (const n of namesToSync) {
    if (enable) removeExcludeFromJsonConfig(globalPluginsJson, n, targetDir);
    else addExcludeToJsonConfig(globalPluginsJson, n, targetDir);
  }
} else {
  // Connected Library Plugin:
  // Manifest must stay clean (disabled: false) so projects can load it
  setPluginManifestDisabled(targetDir, false);
  removeAntigravityPluginFromConfig(dirName);
  // Sync strictly via entry.exclude in plugins.json
  for (const n of namesToSync) {
    if (enable) removeExcludeFromJsonConfig(globalPluginsJson, n);
    else addExcludeToJsonConfig(globalPluginsJson, n, targetDir);
  }
}
```

## 6. Защитные механизмы интерфейса (Guardrails & UI UX)

Чтобы пользователь никогда не попадал в ловушку мертвого состояния (Кейсы G4), расширение внедряет систему умных предупреждений и автоматического решения:

1. **Индикатор статуса `🔴 Заблокирован (ядро)`:**  
   Если ресурс находится в стандартной дефолтной папке, глобально отключен, но при этом пользователь выбрал `✓ Вкл` для текущего проекта:
   - Индикатор статуса принимает вид красной точки с текстом `Заблокирован (ядро)`.
   - Всплывающая подсказка четко объясняет причину:
     > *"Навык/Плагин подключен в .agents/..., но заблокирован ядром Antigravity из-за глобального отключения в ~/.gemini/config/... Переместите его в библиотеку [→] для работы в проекте."*
2. **Предупреждающая модалка при включении в проекте:**  
   При попытке нажать `✓ Вкл` в трехпозиционном переключателе проекта для отключенного дефолтного ресурса открывается системный диалог:
   - Предлагает 1 кликом выполнить действие **«Переместить в библиотеку...»**.
   - При выборе этого действия открывается QuickPick библиотек, файл переносится, его глобальное отключение переносится в `entry.exclude`, а для проекта он сразу активируется в `.agents/...`.
3. **Предупреждение при глобальном отключении:**  
   Если пользователь отключает глобальный дефолтный ресурс, который уже принудительно включен в открытом проекте, расширение выводит модальное окно с предупреждением, что данное действие заблокирует ресурс и внутри проекта.

## 7. Памятка для будущих сессий ИИ

1. **Никогда не удаляйте `setPluginManifestDisabled(targetDir, false)` для библиотечных плагинов.** Если в `plugin.json` останется `"disabled": true`, Antigravity IDE никогда не активирует плагин в проекте.
2. **Никогда не пишите в корневой `exclude` для элементов из подключенных библиотек.** Всегда используйте `addExcludeToJsonConfig(path, name, physicalPath)`, передавая третий аргумент `targetPhysicalPath`.
3. **Помните о дуализме IDE и Desktop:** Antigravity IDE смотрит в `plugin.json`, а Desktop 2.0 CLI смотрит в `~/.gemini/config/config.json`. Любое изменение активности должно учитывать обе системы.
