# AGENTS.md — Архитектурная карта проекта и руководство для ИИ

> **КРИТИЧЕСКОЕ ПРАВИЛО ДЛЯ ИИ (AI Maintenance Protocol):**
> Любой ИИ-ассистент, вносящий изменения в структуру файлов, добавляющий новые компоненты или изменяющий ответственность модулей, **ОБЯЗАН** актуализировать данный файл [/AGENTS.md](/AGENTS.md) перед завершением своей сессии.

---

## 1. Обзор архитектуры проекта

**Antigravity Plugin Manager** — расширение для IDE Antigravity (VS Code Fork), предоставляющее графический интерфейс для управления модулями расширения контекста ИИ:
1. **Плагины** (Plugins) — бандлы навыков, правил, хуков и MCP.
2. **Навыки** (Skills) — автономные каталоги с инструкциями `SKILL.md`.
3. **Воркфлоу** (Workflows) — пошаговые markdown-сценарии.
4. **Правила** (Rules) — глобальные, проектные (`.agents/rules/`) и плагинные правила.
5. **Хуки** (Hooks) — жизненный цикл команд (`hooks.json`).
6. **MCP Серверы** (MCP) — конфигурации серверов Model Context Protocol (`mcp_config.json`).

## 4. Важные технические ограничения и паттерны

1. **Физическое перемещение плагинов (Plugin Toggle Engine):**
   - IDE Antigravity игнорирует NTFS Directory Junctions в папке `~/.gemini/config/plugins/`.
   - **Включен:** физическая папка находится в `~/.gemini/config/plugins/<name>`, а в `storage` создается Junction, указывающий на нее.
   - **Отключен:** Junction в `storage` удаляется, а физическая папка перемещается обратно в `storage/<name>`.
2. **Встроенные системные компоненты (Built-in Components):**
   - IDE Antigravity поставляет встроенные навыки и конфигурации в каталоге `~/.gemini/antigravity-ide/builtin` (например, `builtin/skills/agy-customizations`, `builtin/skills/antigravity_guide`, `builtin/skills/permissioned-github`, а также `antigravity-ide/mcp_config.json`).
   - Отображаются с пометкой `isBuiltin: true`, `isProtected: true` и бейджем «Встроенный» (`res-builtin`).
   - **Строго Read-Only**: тумблер активности скрыт/заблокирован (всегда активны), кнопки перемещения и удаления отсутствуют в UI и жестко блокируются бэкендом. Просмотр файлов в редакторе разрешен.
3. **Защищенные глобальные правила:**
   - Глобальные правила ограничены двумя системными файлами: `~/.gemini/GEMINI.md` и `~/.gemini/AGENTS.md`.
   - Их запрещено удалять или перемещать (`isProtected: true`). Создание новых глобальных правил заблокировано на уровне бэкенда и валидации UI (правила создаются в рабочих проектах или плагинах).
4. **Хуки (Hooks):**
   - Файлы `hooks.json` поддерживаются в Global (`~/.gemini/config/hooks.json`), Builtin, Workspace (`.agents/hooks.json`) и Plugin (`plugins/<name>/hooks.json`).
   - Переключение статуса активности хука производится прямой записью поля `"enabled": true/false` в соответствующем `hooks.json`.
5. **Модульность архитектуры:**
   - Фронтенд изолирован в каталоге `/webview/`.
   - Бэкенд разделён на чистые модули в `/services/` (`fsUtils.js`, `scanners.js`, `actions.js`). Файл `extension.js` выступает компактным оркестратором.
6. **Иерархия отображения и нумерация элементов (4-Tier Order, Numbering & Grouping Toggle):**
   - Во всех вкладках списков ресурсы строго разделяются по 4 уровням:
     1. `Глобальные` (Global) — общие конфигурации пользователя (`~/.gemini/`)
     2. `Локальные (Workspace)` — ресурсы текущих рабочих проектов (`.agents/`)
     3. `Встроенные` (Built-in) — системные компоненты IDE Antigravity
     4. `Из плагинов` (From Plugins) — ресурсы, упакованные в плагины
   - Карточки снабжаются непрерывными номерами `#1`, `#2`, `#3`... и цветными бейджами скоупа (`.res-global`, `.res-local`, `.res-builtin`, `.res-plugin`).
   - Кнопка на тулбаре позволяет включать/выключать визуальную группировку разделителями (`.group-header`). **По умолчанию группировка выключена**, обеспечивая компактный монолитный список без лишнего скролла.
7. **Вкладка «Активное» (Active Context Dashboard):**
   - Стартовая вкладка интерфейса, служащая пультом управления текущим контекстом ИИ.
   - Выводит только реально действующие компоненты:
     1. Компактную плашку включенных плагинов (`.active-plugins-bar`) с чипсами и быстрым выключением в 1 клик.
     2. 5 сворачиваемых категорий: Действующие правила, Действующие навыки, Действующие воркфлоу, Действующие MCP серверы, Действующие хуки.
   - Внутри категорий отсутствуют промежуточные разделители уровней, ресурсы упорядочены логически (`Global -> Local -> Builtin -> Plugins`), а каждый блок можно свернуть кликом по заголовку.
8. **Управление MCP серверами, хуками и ресурсами плагинов:**
   - Для всех карточек ресурсов (правила, навыки, воркфлоу, MCP, хуки) выводится явный цветовой индикатор статуса:
     - **Зеленая светящаяся точка (`#34d399`)**: активный ресурс (включен глобально/локально, встроенный системный или из включенного плагина).
     - **Красная светящаяся точка (`#ef4444`)**: отключенный ресурс (отключен в storage, выключен тумблером или отключен родительский плагин).
   - Для навыков и воркфлоу из плагинов отображаются статусы «Активен (плагин включен)» или «Отключен (плагин выключен)».
   - Глобальные и проектные MCP снабжены тумблером, пишущим `"disabled": true` в `mcp_config.json`.
   - Для хуков тумблер синхронизирован с полем `"enabled": true/false` в `hooks.json`.
   - Разблокирована кнопка перемещения (`→`) для вложенных ресурсов плагинов: их можно переносить между различными плагинами, в глобальные папки или в рабочие проекты.
   - Бейдж плагина (`Плагин: <имя> ↗`) и кнопка в действиях карточки позволяют в 1 клик перейти к управлению плагином с сохранением истории навигации.
   - Кнопка «Открыть в редакторе» (`openFileInEditor`) открывает файл напрямую в VS Code, автоматически находя `SKILL.md` или `plugin.json` для папок навыков и плагинов.
9. **Детали плагина (Plugin Details View):**
   - Липкая шапка `.detail-header` содержит постоянные кнопки управления самим плагином: кнопку «Открыть папку» (открывает директорию плагина в Проводнике ОС через `vscode.env.openExternal`), тумблер активности, кнопку перемещения и кнопку удаления. Они доступны всегда, независимо от того, какие ресурсы есть в плагине.
   - Внутри карточки деталей динамически отображаются все 5 категорий вложенных ресурсов: Навыки (`Skills`), Правила (`Rules`), Воркфлоу (`Workflows`), MCP Серверы (`MCP`), Хуки (`Hooks`).
   - Для всех ресурсов плагина отображаются цветные индикаторы активности (зеленая точка `#34d399` если плагин включен, красная `#ef4444` если выключен).
   - Если плагин не содержит ресурсов, выводится адаптивное уведомление `noPluginResources`.
10. **Кнопка «Обновить / Перепарсить» (Refresh Engine):**
   - Добавлена на тулбар основного окна, в шапку деталей плагина (`.detail-header`) и в заголовок панели VS Code (`sidebar view title`, команда `antigravity-plugin-manager.refresh`).
   - При нажатии запускает CSS-анимацию вращения иконки (`.refresh-spin-icon.rotating`) и отправляет команду `refresh` в бэкенд расширения.
   - Бэкенд расширения выполняет полный повторный сбор данных (`collectAllData`) и обновляет Webview, статус-бар и все списки без необходимости перезагрузки IDE (`Developer: Reload Window`).
